# Data storage defaults for local personal tools (SQLite vs Excel/CSV)

Scope: what an AI agent should choose, and how it should behave, when a non-programmer's small tool must keep or touch data. Registry/PyPI/npm facts were queried live on 2026-09-29. Items not verified are marked [UNVERIFIED] or [INFERENCE].

## Recommendations

1. **Ask one question before choosing storage: "Who is the source of truth, and will a human open, edit or email this file?"** Use the decision table below. Rule of thumb: if the *app* creates and updates the records, use SQLite. If *she* creates and edits the records in Excel, leave them in her file. SQLite's own guidance: it "competes with fopen()", suits application file formats, and is a single file that "can be written to a USB memory stick or emailed" [1][2]. Excel is right when the human is the editor and the recipient is a human [11].

2. **Do not create a database for v1 if the app only reads a spreadsheet and produces a report.** Read her file, write a *new* output file, and stop. Introduce SQLite only when the app has data of its own: history, new records, settings, or state that survives between runs. This follows the build-trap principle. It also avoids the "half-migration" trap of two live copies of the same data [55]. That source is a low-quality vendor blog; the point is weak evidence, so treat it as opinion.

3. **App-owned data goes in one SQLite file in the per-user application-data folder, not in Documents, Desktop, or any synced folder.** Windows: `%LOCALAPPDATA%\<AppName>\`. macOS: `~/Library/Application Support/<AppName>/`. [INFERENCE: these folders are not synced by default.] OneDrive backs up Desktop and Documents [22]. On macOS, iCloud's "Desktop & Documents Folders" setting stores both in iCloud, and new files there go to iCloud automatically [23]. SQLite warns that network-filesystem locking is unreliable and that this can cause corruption [1][3][5]. Practitioners report synced folders as a repeat cause of corruption [26].

4. **Never write into the user's original spreadsheet.** Copy it to a backup folder (timestamped, with a SHA-256 in the log), read from the copy, and write results to a *new* file (`Report 2026-09-29.xlsx`). Save to a temp name in the same folder and rename once complete. openpyxl overwrites without warning [27]; a round trip through a library can silently drop content (see the pitfalls list) [27][30][36][37].

5. **Standard pattern once the app needs data of its own: "read Excel → own SQLite → export Excel".** The spreadsheet is *input only*. The app never edits it. The app owns the SQLite records. The export is a fresh, correctly typed xlsx (or PDF) for people. Keep an `import_log` table (file name, hash, timestamp, rows read/inserted/updated/skipped, warnings). Make re-import idempotent using a stable row key or content hash. Tell her plainly: "Changes you make in the spreadsheet after import don't flow back unless you import again."

6. **If she insists the app change her existing .xlsx, run an escalation ladder and stop at the first rung that works.**
   (a) Don't: write a new output file (default).
   (b) Write to a separate "app-managed" workbook the AI created; users can add sheets but not edit app columns.
   (c) Inject values into her file with a library that preserves the package XML (xlsx-populate) or with Excel itself (xlwings; requires Excel installed) [36][52]. First run a round-trip fidelity test on a copy: unzip both files and diff the part list and the `<dataValidations>`, `<drawing>`, and styles parts [36].
   (d) openpyxl only after the same test passes. It documents that unsupported items are lost, and it removes unsupported extensions with only a warning [27][30].
   Never edit `.xlsm` (macros) in place: openpyxl's `keep_vba` preserves macros but they are "not editable", and mismatched extensions produce files Excel refuses to open [27].

7. **Treat any library warning on load as a stop sign.** For example, openpyxl's "Data Validation extension is not supported and will be removed". The maintainer says that saving after that warning permanently removes the extension and there is no workaround [30]. Never suppress warnings; report to her in plain words ("your dropdown lists would be lost") and fall back to rung (a).

8. **Preflight the file before touching it.** (i) Locked: if the file is open, Excel holds a lock and a hidden `~$name.xlsx` owner file exists next to it. An orphaned owner file after a crash causes false "locked" errors [18][19]. A Python `PermissionError [Errno 13]` on save is the classic symptom [25]. Say: "Please close the spreadsheet in Excel, then tell me." Copy the original to a temp file, then read the copy, so the app holds no handle on the original (openpyxl read-only mode is lazy and the workbook "must be explicitly closed") [54]. (ii) Cloud: if the path is in OneDrive/SharePoint/iCloud, tell her the file is synced. OneDrive Files On-Demand is on by default and "online-only" files download when opened [21]. AutoSave/sync can create conflicted "Copy" files or "Can't Save Your Changes" merge errors [24]. Do not write into synced folders while Excel is open. (iii) Format: detect `.xls` (legacy), `.xlsm`, password-protected files, and >1,048,576 rows (Excel's limit) [20] and stop with a plain explanation.

9. **Validate the sheet's shape against a contract, never by position.** Locate the header row by scanning for expected column names (trim, case-fold). Refuse with a specific diff if columns are missing, renamed, or duplicated. Detect merged cells, blank spacer rows, totals rows, notes above the header, and multiple tables per sheet. Humans add all of these; the recognised rules for data-friendly spreadsheets are: one header row, one rectangle, one thing per cell, no colour-as-data, no calculations mixed into raw data [11]. Ask her to confirm the detected layout in her own words before importing ("I see 3 columns: Name, Date, Amount; the first row is the header; 212 rows. Right?"). Sheet-name lookup must tolerate renames: match by name, fall back to position, and warn.

10. **Read cached values; never treat formulas as inputs.** openpyxl "never evaluates formula"; `data_only=True` returns "the value stored the last time Excel read the sheet", which is `None` for a file no Excel has calculated [27][29]. A workbook loaded with `data_only=True` then saved has values instead of formulas [INFERENCE from 27]. When writing formulas, XlsxWriter stores 0 as the result and flags Excel to recalculate on open, so viewers that do not calculate show 0 [34]. Use US-English function names and comma separators in stored formulas; newer functions need the `_xlfn.` prefix [29][34]. Rule: write formulas only for humans to see; the app must never read them back.

11. **Convert types at the boundary, and make dates explicit.** SQLite has no date type; store ISO-8601 text (`YYYY-MM-DD`) [9]. Excel stores dates as serial numbers and treats 1900 as a leap year (a deliberate Lotus-compatibility bug); only `WEEKDAY` for pre-March-1900 dates is affected in practice [15]. openpyxl also supports the 1904 epoch, holds no timezones, and documents that pre-1900 dates are not suitable for xlsx [28]. Write real date cells with a `number_format`; never write locale-formatted date strings. Use `STRICT` tables so the database rejects wrong types instead of coercing them [10].

12. **Store identifiers as text and warn about Excel's auto-conversion.** Zip codes, phone numbers, order numbers, and SKUs like `1E5` or `2310009E13` must be `TEXT` in SQLite and text-formatted cells in xlsx. Excel keeps only 15 significant digits [20]. Evidence of auto-conversion damage is large: gene symbols such as SEPT2 became dates ("2-Sep") and identifiers became floats; a 2016 screen of 35,175 supplementary Excel files found errors in 19.6% of papers with gene lists (704 papers) [13]. A 2021 re-scan found 30.9% (3,436 of 11,117) and identified an extra failure mode, five-digit serial numbers [14]. Excel and Google Sheets converted names in all three modes tried (open, paste, type); formatting destination cells as plain text avoided it [14]. In pandas, read with `dtype=str` to keep values uninterpreted [45].

13. **Prefer xlsx over CSV as the file format handed to her.** If CSV is unavoidable, follow these rules. **Read:** open with `newline=''`; the `csv` module does no type conversion [48]; decode `utf-8-sig` to strip a BOM [49]; sniff the delimiter [48] because the list separator comes from the Windows regional setting, and in decimal-comma locales Excel uses a semicolon [16]. **Write for Excel:** UTF-8 *with* BOM (Excel opens UTF-8 CSV "normally if it was saved with BOM"; otherwise the user needs a Data > From Text/CSV import) [17]. Match the delimiter to her locale (ask "do you write 3,5 or 3.5?" rather than "what delimiter?") [16]. Warn her that double-clicking a CSV applies "current default data format settings" [16], which strips leading zeros and converts dates. **Security:** neutralise cells beginning with `=`, `+`, `-`, `@`; OWASP notes Excel-specific caveats and that there is no universal sanitisation [51].

14. **Write new xlsx with XlsxWriter (Python) or ExcelJS (JS, new files only); style it for humans.** Header row bold, frozen, autofilter, sensible column widths, real number/date formats, one table per sheet. XlsxWriter "cannot read or modify existing" files but produces files "100% equivalent" to Excel's in most cases [33]. Include a `README`/"About" sheet with export date and source. Reopen the file with a reader and compare row counts after writing.

15. **SQLite defaults for AI-generated apps.** One writer connection, `PRAGMA foreign_keys=ON` (node:sqlite already defaults to it [42]), `STRICT` tables [10], a busy timeout, all writes in transactions. Prefer the default rollback journal for a single-user desktop tool unless a concurrency need is shown. WAL adds `-wal`/`-shm` sidecar files, cannot work over a network filesystem, and SQLite notes it makes the DB "less appealing for use as an application file-format" [4]. Losing or copying the DB file without its sidecars corrupts it [5]. (better-sqlite3 and Bun recommend WAL for performance [39][41], but personal-scale data does not need it.) Use parameter binding always [50].

16. **Backups: `VACUUM INTO 'backup-YYYY-MM-DD.db'` (or the language's backup API) automatically before any import, migration, or bulk delete; never copy a live DB file.** SQLite lists VACUUM INTO, the backup API, and `sqlite3_rsync` as safe ways to copy a live DB; a plain copy during a transaction may be corrupt [5][6]. The target file must not already exist (or must be empty) [6]. Also available: Python `Connection.backup` [50], `node:sqlite` `backup()` (since v22.16/v23.8) [42]. Keep the last N backups, run `PRAGMA integrity_check` on the fresh backup, and restore one at least once during the app's development [26]. Backups belong in a folder she can find (e.g. `Documents/<App> backups`); warn if that folder syncs to the cloud.

17. **Migrations: a numbered list of idempotent migration steps and `PRAGMA user_version`.** The user-version integer lives in the database header and is left entirely to the application [7]. At startup: read `user_version`, take a backup, run pending steps in one transaction, bump `user_version`. Prefer additive changes (`ADD COLUMN`, new tables), which do not change the meaning of old queries [2][8]. For anything else (change type, add constraint, drop/reorder columns) use the documented 12-step create-new/copy/drop/rename procedure [8]. The AI must never "recreate the schema" on a DB that holds her data. Test every migration on a copy of a real database.

18. **Ship an escape hatch: "Export everything to Excel" (one sheet per table) and "Back up now" buttons.** SQLite's "single-file document" model (copy, email, attach) fits her mental model of a document; the database schema is also the documentation of the file [2]. Name the file in her vocabulary and give it an app-specific extension or a plain `.db` name she can recognise.

19. **Provide history in SQLite, not in Excel.** If she needs "what changed / undo / who did this", add an append-only `history` (or soft-delete flag) table; SQLite explicitly supports trigger-managed undo/redo stacks in the file [2]. Spreadsheet errors are "silent", "hidden among thousands of rows", and "difficult to audit" [14]. In field audits since 1995, 88% of 113 audited spreadsheets contained errors [12].

20. **Library defaults** (details in the verification table). Python: `sqlite3` stdlib + `python-calamine` or `openpyxl` (read) + `XlsxWriter` (write new) + `csv` stdlib; add pandas only for heavy analysis. JS/Bun: `bun:sqlite` on Bun; `node:sqlite` on Node ≥24 (release candidate) or `better-sqlite3` ≥13 on Node ≥22; SheetJS (from the CDN tarball) or `read-excel-file` for reading; ExcelJS for writing new files only; `papaparse` for CSV. Pin versions and record them in the app's README. Re-verify wheel/prebuild availability for the exact runtime version at install time.

### Decision table: SQLite vs xlsx vs CSV

| Question | SQLite file | Excel .xlsx | CSV |
|---|---|---|---|
| Who is the source of truth? | The app | The human | An exchange copy only |
| Who edits records? | The app's UI; humans only via SQL tools | Human, in Excel | Nobody; export/import step |
| Shared by email? | Possible but the recipient can't open it [1] | Yes; recipient opens it | Yes, but Excel may mangle types/encoding [16][17] |
| Row counts | Up to very large; fine for personal data [1] | ≤1,048,576 rows per sheet [20]; slow well before | Same; no cap in the format |
| Relational structure (many-to-many, lookups) | Native: keys, constraints, joins [2] | Awkward; VLOOKUP and copies | None |
| History / audit | Add tables/triggers [2] | Weak; errors silent [12][14] | None |
| Data types | Strict types (opt-in) [10]; dates as ISO text [9] | Auto-conversion risk [13][14]; 15 digits [20]; date serials [15] | Untyped text; the reader guesses |
| Formatting, formulas, charts | None | Yes | None |
| Concurrent writers | Single writer; local disk only [1][3] | One editor at a time (locks) [18] or cloud co-authoring | n/a |
| Safe in a OneDrive/iCloud folder? | **No** [3][5][26] | Yes if closed; AutoSave can conflict [24] | Yes |
| Best use here | App-owned data; history; state | Human-owned data; reports she opens | Import from other systems; hand-off to non-Excel tools |

### Spreadsheet I/O pitfalls and mitigations

| Pitfall | Evidence | Mitigation |
|---|---|---|
| File locked while open in Excel; hidden `~$` owner file; orphaned owner file | [18][19][25] | Detect `~$` file / catch `PermissionError`; ask her to close; read from a temp copy; never write to the original |
| OneDrive/SharePoint sync conflicts, AutoSave merges, "Copy" files | [24] | Detect synced path; write outputs to a new file; warn before writing in synced folders |
| iCloud/OneDrive silently uploading Desktop/Documents | [22][23] | Store the DB in app-data folder; tell her where output files go |
| Round trip drops charts/images/shapes/extension validations/macros | openpyxl [27][30], ExcelJS [37], SheetJS CE and ExcelJS in a 2026 test [36] | Prefer new output files; unzip-diff round-trip test; treat warnings as errors; refuse `.xlsm` |
| Formulas not recalculated; no cached value | [27][29][34] | Read cached values only; don't read back formulas; let Excel recalc on open |
| Date serials; 1900 leap-year bug; 1904 epoch; no timezones | [15][28] | Convert dates at the boundary; ISO text in SQLite; real date cells with number format; check `wb.epoch` |
| Leading zeros, >15-digit IDs, gene-like names converted | [13][14][16][20] | Text columns; text-format cells; `dtype=str`; xlsx not CSV for hand-off |
| CSV: semicolon delimiter, decimal comma, ANSI/UTF-8 BOM | [16][17][49] | `utf-8-sig`, sniff delimiter, choose delimiter by locale, warn on double-click |
| CSV formula injection | [51] | Neutralise leading `= + - @` for human-opened CSV |
| Merged cells, spacer rows, totals rows, notes above header | [11] | Contract check on headers; ask her to confirm layout; refuse rather than guess |
| Users rename columns/sheets, reorder, add columns | [11] | Match by header name; report diff; never index by column number |
| Silent data corruption | [12][13][14] | Backups, hashes, import log, row-count comparison after every write, plain-language summary of what was read |

## Key evidence

**Which store fits (Rec. 1–3, 5, 18–19).** SQLite says it "does not compete with client/server databases. SQLite competes with fopen()." Its recommended domains include application file formats, replacing ad-hoc disk files, and data analysis; a database is "a single file that can be written to a USB memory stick or emailed to a colleague" [1]. Its checklist for engine choice ends "Otherwise → choose SQLite!" for device-local storage [1]. The application-file-format whitepaper lists benefits relevant to an AI-built app: no new file-format code, single-file documents, atomic transactions, easy extension by adding tables/columns, concurrent readers, trigger-based undo/redo, and a schema that documents the format [2]. Spreadsheet-side evidence is about *risk*, not fit: Panko's field audits found errors in 88% of 113 audited spreadsheets since 1995 [12]; Broman & Woo give data-entry rules (single header row, one thing per cell, ISO dates, no calculations in raw data, backups, plain text for storage) [11]; Abeysooriya et al. conclude spreadsheet errors "occur silently, … can be hidden amongst thousands of rows, and … are difficult to audit" [14]. Read together: these say spreadsheets are fine for human editing and viewing, dangerous as the sole system of record.

**Synced folders and locking (Rec. 3, 8, 15–16).** SQLite: file locking "is buggy in many network filesystem implementations," so corruption can occur; WAL "does not work over a network filesystem"; and copying the DB or deleting journals/WAL mid-transaction can corrupt it [1][3][4][5]. Microsoft: Desktop/Documents can be backed up to OneDrive [22], Files On-Demand is on by default [21]; Apple: Desktop and Documents can be stored in iCloud Drive and new files go there automatically [23]. Microsoft's locked-file pages explain Excel's owner file `~filename.xlsx` [19] and that non-Microsoft-365 locations such as local folders, network shares, and Dropbox do not support co-authoring, producing "locked" errors [18]. A Microsoft Q&A thread describes "Can't Save Your Changes … couldn't merge your changes" errors on OneDrive-hosted Excel files even for a solo user [24]. A 2026 practitioner post reports the same pattern for SQLite state files in synced folders and recommends excluding the directory and using `VACUUM INTO` or the backup API [26] (opinion, consistent with [5]).

**Library round-trip fidelity (Rec. 4, 6–7, 14).** openpyxl docs: it "does currently not read all possible items in an Excel file so shapes will be lost from existing files if they are opened and saved with the same name"; `save()` "will overwrite existing files without warning"; `keep_vba` keeps macros but "they are still not editable" [27]. On load it warns that unsupported data-validation/conditional-formatting extensions "will be removed"; the maintainer replies that there is currently no way around this [30]. openpyxl changelog shows chart *read* support was added, followed by years of reader bug fixes for specific chart types [32]. ExcelJS: an open feature request records that it "removes the charts when reading the file" [37]. One practitioner (2026) compared ExcelJS, SheetJS 0.18.5 and xlsx-populate on a workbook with cross-sheet dropdown validations, drawings and styles, and inspected the XML: ExcelJS duplicated validations (7→14) and lost drawings; SheetJS dropped validations, drawings and most styles; xlsx-populate preserved everything [36]. This is a single test by one person, not a benchmark. XlsxWriter is explicit: it cannot read or modify existing files [33]. xlwings automates Excel itself and requires Excel to be installed [52].

**Formulas and dates (Rec. 10–11).** openpyxl: `data_only` "controls whether cells with formulae have either the formula (default) or the value stored the last time Excel read the sheet" [27]; "openpyxl never evaluates formula" [29]. XlsxWriter stores 0 as the formula result and sets a recalculate-on-open flag; formulas must use US-English names and commas [34]. Microsoft explains that Excel keeps Lotus 1-2-3's leap-year error for 1900 for compatibility, and that fixing it would shift almost all dates by a day [15]. openpyxl documents the 1900/1904 systems, no timezone support, and ISO-date mode [28]. SQLite has no date storage class; ISO-8601 TEXT is one of three recommended representations [9].

**Auto-conversion and CSV (Rec. 12–13).** Ziemann et al. 2016 screened 35,175 supplementary Excel files; 987 files in 704 papers (19.6% of papers with gene lists) contained gene-name errors (SEPT2 → date; `2310009E13` → `2.31E+13`); the problem was first documented in 2004; Google Sheets did not convert on typing/pasting in their test [13]. Abeysooriya et al. 2021: 30.9% (3,436/11,117); Excel and Google Sheets converted in all three input modes and LibreOffice/Gnumeric did not; the fix in Excel was pre-formatting cells as text; HGNC renamed genes (SEPT1→SEPTIN1) to dodge it [14]. Microsoft: opening a CSV uses "current default data format settings"; forcing the wizard (rename `.csv`→`.txt`) preserves leading zeros; the CSV list separator comes from regional settings and a decimal comma forces a semicolon; the limit is 1,048,576 rows [16]. UTF-8 CSV opens correctly only "if it was saved with BOM"; otherwise use Data > Get Data > From Text/CSV [17]. Excel numbers have 15-digit precision [20]. Python's `utf-8-sig` writes/skips the BOM [49]; `csv` needs `newline=''` and does no type conversion [48]. OWASP: cells starting `=`, `+`, `-`, `@` may run as formulas; the tab-prefix mitigation is Excel-specific and pollutes the data [51].

**SQLite hygiene (Rec. 15–17).** SQLite's corruption guide lists safe live-copy methods (`sqlite3_rsync`, `VACUUM INTO`, backup API) and warns about backing up during a transaction and about moving/deleting hot journals [5]. `VACUUM INTO` needs a non-existent or empty target and creates a consistent snapshot; an interrupted run can leave an incomplete file [6]. `PRAGMA user_version` is a free integer "for applications to use however they want" [7]. `ALTER TABLE` supports rename/add/drop column directly; other changes need the 12-step procedure [8]. STRICT tables (3.37.0, 2021-11-27) enforce declared types, unlike SQLite's default flexible typing [10]. WAL is faster and allows readers alongside a writer but adds sidecar files and needs same-host access [4]. Node's `node:sqlite` enables foreign keys by default [42].

**Runtime and install (Rec. 20).** better-sqlite3 13.0.3's npm tarball contains `prebuilds/win32-x64.node`, `win32-arm64.node`, `darwin-x64.node`, `darwin-arm64.node` (and Linux), has no install script, and declares Node ≥22; verified by downloading and listing the tarball [39][40]. Bun's `bun:sqlite` needs no install; on macOS it uses Apple's SQLite, elsewhere a static build [41]. Node's `node:sqlite` is Stability 1.1 on 22.x, 1.2 RC on 24.x and later [42]. Python's `sqlite3` is an optional module, but python-build-standalone statically links SQLite into it [46][50], and uv installs those builds into the user profile [47]. SheetJS: the npm `xlsx` is stale (0.18.5); the authoritative source is `cdn.sheetjs.com`, current 0.20.3 [35]; the tarball metadata shows Apache-2.0 and no dependencies [53]. Wheel coverage for pandas, polars-runtime-32, python-calamine was read from PyPI's JSON API [43].

## Open questions and disagreements

- **WAL or not.** better-sqlite3 and Bun docs recommend WAL for performance [39][41]; SQLite's own docs list sidecar files and no network-filesystem support as WAL drawbacks, particularly for application file formats [4]. Recommendation 15 favours the default rollback journal at personal scale; this is a judgment, not measured.
- **openpyxl fidelity has no authoritative matrix.** Docs say "shapes" are lost [27]; charts and images are partly supported and image support needs Pillow [27][32]. Results depend on the file; hence the unzip-diff test. Last stable release is June 2024 [31] (a 3.2.0b1 pre-release exists), so maintenance is slow [INFERENCE].
- **xlsx-populate is a single-blog recommendation** and the package's last release is 2020 [36][40]. Treat it as an option to test, not a default.
- **SheetJS licence/limitations.** CE is Apache-2.0 [53]; its docs page on styling was not retrievable, so "styling is Pro-only" rests on a search summary and the 2026 test [36] [UNVERIFIED].
- **Can the app read a file while Excel has it open?** Windows evidence is about write failures and lock files [18][19][25]; I did not verify read behavior or macOS behavior [UNVERIFIED]. The copy-to-temp approach avoids the question but may itself fail.
- **Does a script's read trigger OneDrive hydration?** Microsoft says online-only files download when opened [21]; a vendor blog claimed plain filesystem reads from tools may not trigger it (search snippet, not verified) [UNVERIFIED].
- **Where are app-data folders synced?** I found no source stating `%LOCALAPPDATA%` or `~/Library/Application Support` are excluded from OneDrive/iCloud; the recommendation rests on the documented scope (Desktop/Documents) [22][23] [INFERENCE].
- **Thresholds ("more than three editors", row counts).** Vendor blogs give team-scale thresholds [55]; they do not apply to single-user tools. Only the hard limit (1,048,576 rows) is sourced [20]. Practical "slow" limits for Excel are unmeasured.
- **Bun on macOS uses the OS's SQLite** [41]; feature availability (STRICT tables, `VACUUM INTO`) then depends on the macOS version [INFERENCE]; check `sqlite_version()` at startup.
- **better-sqlite3 13.x is recent** (13.0.0 released 2026-07-21) [40]; AI training data will describe the older `prebuild-install`/node-gyp flow.
- **Excel formula recalculation without Excel** (LibreOffice headless or Python formula engines) was not researched; it likely needs a separate install [INFERENCE].

## Conflicts with the guiding principles

- **Local-first / "data never leaves the machine without her knowing" vs. Known Folder Move.** On many office PCs, Desktop and Documents are already redirected into OneDrive [22]; on macOS the same may hold for iCloud [23]. Saving app output, backups, or the database into "Documents" therefore uploads it, silently to her. The skill must check the path and either keep app data in the app-data folder or tell her explicitly.
- **Smallest-useful-thing vs. the "read Excel → own SQLite → export Excel" pattern.** The pattern adds a database and an importer. Applied at v1, it breaks the build-trap principle (Rec. 2 addresses this by making SQLite conditional on the app having data of its own).
- **"AI picks technology" vs. questions about her files.** The skill must ask about her data ("who else edits this file? do you email it?") but not about technology. This is compatible, provided questions use her vocabulary.
- **No-admin requirement: no conflict for the recommended stack.** Caveats: better-sqlite3's troubleshooting doc points to admin-level "install tools" only as a fallback build path [39], which should not trigger with v13 prebuilds; xlwings requires Excel to be installed (pre-existing, not admin) [52].
